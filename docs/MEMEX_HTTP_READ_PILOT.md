# Memex HTTP read pilot

The Joris enrichment factory now selects an optional server-only HTTP transport before its existing local stdio path. Configure `ORIA_ENABLE_MEMEX_HTTP_READONLY=1`, `MEMEX_HTTP_ENDPOINT`, `MEMEX_HTTP_HQ_WORKSPACE_ID` and `MEMEX_HTTP_READ_HANDLE` in the server secret store. No configuration or credentials have been activated by this change.

The endpoint must be HTTPS with the exact `/mcp` path, or explicit loopback HTTP for a private tunnel. Userinfo, query strings, fragments, redirects and arbitrary internal HTTP hosts are rejected. There is no client-selected URL, credential or project. An enabled but invalid or foreign-workspace HTTP binding fails closed instead of silently falling back to stdio. Cloud execution can use HTTP without spawning local processes; the original stdio gates remain unchanged.

Use an expiring signed `amh1` handle with `access:read_only` and exactly one namespace: `workspaceIdToMemexNamespace(workspaceId)`. For workspace `pilot-a`, this is `org:workspace:pilot-a`. HQ inspects the payload to reject excess scope and expired/malformed configuration; **the Memex server verifies the signature**. HQ never receives the signing secret. Handle renewal remains an operator action. A single binding does not provide a multi-workspace credential registry.

The transport implements the canonical Memex `POST /mcp` stateless JSON-RPC subset: `tools/list` for the existing bridge handshake and allowlisted `tools/call`. It does not require or retain a session, use legacy SSE, retry, write, publish or issue arbitrary RPC methods. Tool calls require the fixed namespace; the existing evidence pipeline independently excludes foreign/unproven facts. Returned records remain untrusted advisory evidence.

Each request has a five-second deadline, a 512 KiB streamed response cap and strict JSON-RPC identity, error and text-content validation. Closing aborts all active reads. Provider diagnostics, URL and handles never appear in transport error messages. Timeout includes stalled response bodies. No token is returned to the browser.

Tests cover read scope, workspace mismatch, write denial, malformed/error/nontext output, size limits, cancellation, deadline and real loopback HTTP through the enrichment factory using synthetic records. A fake loopback responder is not an authenticated live Memex deployment test. Before enabling the remote service, verify the signed handle against the real Memex server, cross-project denial, TLS/private reachability and a synthetic canary through HQ. No DNS-rebinding defence beyond trusted server configuration is claimed; configuration ownership is a deployment boundary.

Optional `node --test src/server/mcp/memex-http-live.test.mjs` skips unless `MEMEX_HTTP_LIVE_TEST=1`. Supply endpoint and a temporary handle only to that process. It invokes the actual enrichment factory for workspace `pilot-a`, expects `memex-pilot-canary-a-v1`, keeps evidence untrusted and verifies the `pilot-b` workspace is refused. This qualifies a backend module through HTTP, not a deployed full application or authenticated browser workflow.
